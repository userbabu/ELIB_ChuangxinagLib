# 取消令牌

`取消令牌` 是可单独使用、可复制共享的取消与暂停控制对象，适用于多个工作线程和三个 HTTP 访问类。构造后立即可用，不需要整数停止标记或传递指针。

## 接口

| 方法 | 返回 | 行为 |
| --- | --- | --- |
| `创建()` | 逻辑型 | 重新开始一轮，创建新的未取消、未暂停状态；旧副本及旧请求绑定不变 |
| `取消()` | 逻辑型 | 取消本轮，唤醒取消和暂停等待；重复调用返回真，重新开始请调用 `创建()` |
| `暂停()` | 逻辑型 | 设置本轮暂停；已取消返回假 |
| `恢复()` | 逻辑型 | 仅恢复暂停；本轮已取消返回假，重新开始请调用 `创建()` |
| `是否已取消()` | 逻辑型 | 查询本轮取消状态 |
| `是否已暂停()` | 逻辑型 | 查询本轮暂停状态；取消后为假 |
| `等待取消(超时毫秒)` | 逻辑型 | 取消返回真，超时返回假；可用于能被取消唤醒的延时 |
| `等待继续(超时毫秒)` | 逻辑型 | 正常运行返回真，暂停则等待恢复；取消或超时返回假 |
| `是否已创建()` | 逻辑型 | 查询是否持有有效状态；取消、暂停后仍为真，不创建或重置状态 |
| `销毁()` | 无 | 解除本变量引用，不自动取消，也不强制结束线程 |

两个等待方法的超时单位均为毫秒，省略或 `-1` 无限等待，`0` 立即检查。系统资源创建或等待失败报告运行时错误，不作为正常超时处理。

## 同时控制三个访问类

三个访问类新增 `绑定取消令牌(令牌，参考)` 与 `解绑取消令牌()`，均返回逻辑型。

```易语言
.版本 2
.支持库 cxsoft

.程序集变量 采集控制, 取消令牌
.程序集变量 Curl请求, HTTP访问_Curl访问类
.程序集变量 WinHTTP请求, HTTP访问_WinHTTP访问类
.程序集变量 WinInet请求, HTTP访问_WinInet访问类

' 在发起请求前绑定，各工作线程使用自己的请求对象。
Curl请求.绑定取消令牌 (采集控制)
WinHTTP请求.绑定取消令牌 (采集控制)
WinInet请求.绑定取消令牌 (采集控制)

' 外部操作其中一项，即控制绑定本轮的所有请求与共享副本。
采集控制.暂停 ()
采集控制.恢复 ()
采集控制.取消 ()
```

以上三条控制命令展示不同操作，并非实际采集代码中需要连续调用的步骤。请求仍使用原访问命令，取消后返回空字节集，`取上次请求错误码()` 为 `1223`；取消不会继续代理重试或重定向，也不会自动复位令牌。

绑定令牌后原整数停止变量绑定解除；绑定整数停止变量或其指针后令牌绑定解除，两种控制源互斥。`解绑取消令牌()` 仅解除该请求对象的令牌引用，不改变其他对象或令牌状态。绑定与解绑应在请求前或返回后调用；请求中调用会等待该对象的访问结束，回调内改绑会报告错误，不能用解绑代替取消。

## 全局快捷请求的可空令牌

以下三个全局命令在最后增加可空的 `取消令牌` 参数，类型为 `取消令牌`，参考传入当前变量；原有参数顺序不变：

| 全局命令 | 参数总数 | 令牌位置 |
| --- | --- | --- |
| `网页_访问_Curl` | 20 | 第20个，位于“模拟浏览器TSL”之后 |
| `网页_访问_WinHTTP` | 17 | 第17个，位于“是否采用Gzip”之后 |
| `网页_访问_WinInet` | 15 | 第15个，位于“是否采用Gzip”之后 |

在易语言参数提示中将最后的“取消令牌”填为共享变量即可，无需先创建访问类或调用绑定方法。省略或留空时保持不绑定的访问方式；传入已取消令牌时不发送请求，传入暂停令牌时等待恢复或取消。外部调用同一令牌的 `取消()`、`暂停()`、`恢复()` 可同时控制这三个全局命令与已绑定的访问类。

每次全局调用固定并持有令牌当前状态引用，在请求结束后随临时对象释放；调用期间原令牌变量销毁不会使请求持有的状态悬空。`创建()` 后的新调用取得新状态，已在运行的调用保留旧状态；控制线程仍应先取消并等待旧任务结束再创建新一轮。

取消时正文和返回头均为空；Curl的“返回错误日志”包含1223。WinHTTP、WinInet全局命令没有返回错误码参数，调用方结合令牌的 `是否已取消()` 判断取消，不应把空正文直接当作成功。暂停边界与访问类一致，系统已发出的网络操作可能继续缓冲。

## 工作线程单独使用

```易语言
.子程序 采集工作线程

.判断循环首 (采集控制.等待继续 ())
    ' 执行一小步采集；每个检查点应在业务锁之外。
    ' 不要在这里强制退出线程，已进入的业务锁必须正常离开。

    ' 代替不可取消的长延时；取消可立即唤醒这里。
    .如果真 (采集控制.等待取消 (100))
        返回 ()
    .如果真结束
.判断循环尾 ()

' 从线程入口返回，控制线程仍需等待线程结束再关闭线程句柄。
```

取消令牌传递取消通知，不会自动解锁业务锁，也不能使任意第三方阻塞调用或被强杀的线程安全恢复。普通 `线程锁.进入()`、其他库的等待和延时不会自动读取令牌，调用方应使用有界等待并在业务安全点检查令牌。

## 复制、绑定与生命周期

`副本 ＝ 采集控制` 共享同一轮状态，对任一副本调用取消、暂停、恢复都会通知同一轮。令牌变量、复制的副本、等待中的调用、绑定的请求对象各自持有引用；只有最后一份引用释放后才关闭事件，避免悬空指针和提前关闭等待句柄。

释放原令牌变量不会破坏仍在使用的副本或请求。HTTP 访问类复制后保留同一轮令牌，Cookie 等配置独立、网络请求与响应缓冲独立；该复制路径按 SDK 的“目标第0参、源第1参”实现。请求对象本身仍须存活到访问返回，令牌不代替其生命周期管理。

同一令牌变量的状态操作、复制、销毁、创建与查询通过生命周期锁和内部状态锁协调；等待前先固定内部引用，系统等待不持有这两把锁。取消不需要获取 HTTP 对象的访问锁，因此能够打断正在暂停或等待网络完成的请求。

同一轮的取消为单向状态，`恢复()` 不能撤销。重新开始任务时：先取消旧轮、等待旧任务和请求全部返回，然后调用 `创建()` 并为请求重新绑定；不需要另定义变量或使用new。创建不会把已有绑定或旧副本搬到新状态，也不会替旧轮发出取消通知，避免旧任务被意外恢复。

重新开始的易语言写法：

```易语言
' 上一轮线程和请求全部结束后执行。
采集控制.创建 ()
Curl请求.绑定取消令牌 (采集控制)
WinHTTP请求.绑定取消令牌 (采集控制)
WinInet请求.绑定取消令牌 (采集控制)
```

`创建()` 是控制线程开启新一轮的操作，不应放在每个工作线程的循环或重复按需初始化路径中；仅检查变量状态请用 `是否已创建()`。

## 暂停边界

暂停是协作式的：`等待继续()` 与访问类内部的控制检查点会阻塞，恢复后继续，取消会唤醒暂停等待并结束请求。暂停调用本身不等待所有工作线程抵达检查点；与暂停同时发生的一小步操作可能完成。

Curl 在 multi 驱动循环检查；WinHTTP、WinInet 在请求前和异步收发等待/分块边界检查。系统已经接收的网络操作可能继续完成或缓冲，暂停不代表 TCP 流量立即归零。网络连接和超时仍遵循各后端规则，暂停过久可能造成服务器断开或请求超时，恢复并不承诺原连接仍可用。

不要持有其他线程取消/恢复所需的业务锁再等待令牌，避免形成业务死锁；不使用 `SuspendThread`、`TerminateThread` 或跨线程释放互斥锁。

## 内存与访问效率专项验证

正常运行的请求检查点只原子读取一次令牌状态并返回，不做内存分配、不读取计时器、不获取令牌生命周期锁。只有暂停等待或修改状态才进入事件/同步路径；绑定持有的引用覆盖整个请求，收发循环不重复申请或释放引用。

`host_cancel.cpp` 额外对所有进程堆执行 `HeapWalk`，在同一进程预热后连续运行6批、每批10000轮令牌复制、请求绑定、重绑定、请求复制、暂停恢复、取消、新轮次、销毁组合；6批的活跃堆内存均为215723字节、892个活块，私有内存均为1908736字节，句柄均为146个，没有逐批增长。分配器保留的空闲页与仍在使用的活块分别观察，避免仅以工作集判断泄漏。

使用MSVC AddressSanitizer对本库及测试宿主进行临时插桩，全部取消/暂停、网络及内存压力测试通过，未报告越界、重复释放、分配释放不匹配或释放后访问；ASan在Windows上的本次运行不作为独立泄漏检测器，泄漏证据来自上述活块、内存与句柄回收测量。第三方curl DLL未重新插桩。

发布构建在本机的公开 `等待继续(0)` 含生命周期引用保护，50万次平均33.2ns/次；HTTP内部检查路径更短，不执行这层引用保护。真实本地HTTP请求预热后各取100个交替样本，整数停止变量/令牌平均耗时：Curl为0.376/0.374ms，WinHTTP为0.794/0.789ms，WinInet为1.424/1.435ms。该数据用于检查本次额外开销，不代表所有机器或公网环境的性能保证。

测试、计时及堆遍历只在离线宿主中执行，发布库不包含这些监测路径，也没有为监测增加后台线程。

## 易语言参数布局与取消延迟验证

成员命令的对象自身通过 `m_pCompoundData` 接收对象数据；`绑定取消令牌` 和全局访问的末尾参数标记为 `AS_RECEIVE_VAR`，必须通过 `m_ppCompoundData` 取得复合变量指向的对象数据，然后读取令牌内部状态。两者不能按同一层指针解析，否则请求可能没有绑定到调用方正在取消的状态，并可能破坏内存。

`host_cancel.cpp` 的绑定与全局请求用独立的“复合变量指针→对象数据→状态”布局构造参数，覆盖SDK的变量引用协议；`host_cover.cpp` 的令牌引用实参也使用相同布局。成员自身与复制参数仍按各自的SDK约定传递。网络取消测试记录从发出取消到调用返回的耗时，不用仅判断请求最终是否结束代替取消响应验证；系统调度和资源回收仍可能影响耗时，不承诺零延迟。

在模拟SDK复合变量引用的本地延迟响应中，已验证调用取消后结束而非继续等待服务器；使用Amazon搜索链接的三轮对照，修复实现取消命令耗时均为0ms，请求在取消后0～16ms返回。全局三个后端覆盖响应头、正文、上传和TLS等待时，发布构建实测最大返回延迟分别为31ms、16ms、31ms；ASan构建相应最大值为32ms、31ms、31ms。该数值为实测，不是硬实时上限。
