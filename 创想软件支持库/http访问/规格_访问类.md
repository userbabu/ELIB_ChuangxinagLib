# 当前支持库的请求取消接口

三个访问类均支持参考整数或整数指针绑定停止标记，原子置 `1` 后取消正在进行的请求。命令签名、错误码、线程约束和调用示例以 [停止变量绑定](停止变量绑定.md) 为准；三个全局命令 `网页_访问_Curl`、`网页_访问_WinHTTP`、`网页_访问_WinInet` 还在末尾提供可空 `取消令牌` 参数，分别为第20、17、15个参数，传入后控制本次调用的取消、暂停、恢复；原有参数位置不变，省略不绑定。令牌引用与生命周期见[取消令牌](../线程锁/取消令牌.md)。以下章节保留各访问命令的原有参数、Cookie 和协议处理规格。

> 只读分析产物，供另一个 agent 照抄写 C++ 原生支持库。所有类名、成员命令名、参数名/顺序/类型/可空性均逐字摘自源码。
> 源目录：`ecode\代码\`（`cURL类\`、`WinHTTP类\`、`WinInet类\`）、`ecode\代码\通用公开函数.static.e.txt`、`ecode\代码\通用模块.static.e.txt`、`ecode\常量.e.txt`、`ecode\模块\zyCurl\`（外部 curl 封装支持库）。
> 本文档不含 C++ 代码。所有"参考/可空"沿用易语言含义：`参考`=指针出参（调用者传变量地址，被调方写回）；`可空`=调用时可省略（省略时按易语言规则填该类型零值：整数=0、文本=""、逻辑=假、字节集=空）。

## 关键外部依赖（迁移前须知）

- **`curl_http` 类**（类型名 `curl_http`，来自外部支持库 `zyCurl`，文件 `模块\zyCurl\代码\curl_http.class.e.txt`）：是 libcurl-impersonate 的封装类，方法体不在导出的 txt 里（编译在 zyCurl 的 .fne 内）。`HTTP访问_Curl访问类` 通过成员变量 `CURL类`（类型 curl_http）调用它。方法语义（按类声明的注释）：
  - `创建()`→curl_easy_init（重建 easy 句柄）；`销毁()`→curl_easy_cleanup；`取句柄()`/`置句柄(整数)`→读写 CURL* 指针。
  - `置选项(选项整数, 值整数)`→curl_easy_setopt（长整数版 `置选项长整数`；文本版 `置选项文本`；字节集版 `置选项字节集`）。返回 CURLE_ 常量，成功=0。
  - `置URL(文本)`→CURLOPT_URL；`执行()`→curl_easy_perform 返回 CURLE_ 码；`取响应头()`→返回头文本；`取响应数据()`→返回响应体字节集；`取响应代码()`→HTTP 状态码。
  - `置进度回调2(子程序整数指针, 用户数据整数)`→CURLOPT_XFERINFODATA/CURL_PROGRESSDATA + 回调（等价 CURLOPT_PROGRESSFUNCTION，5 参回调）。
  - `置POST(逻辑)`→CURLOPT_POST；`置POST数据字节集(字节集)`→CURLOPT_POSTFIELDS(+SIZE)；`置POST数据(文本)`。
  - `模仿(target文本, default_headers逻辑可空)`→**curl_easy_impersonate**（curl-impersonate 专有 API）。
  - `置协议版本(整数 #CURL_HTTP_VERSION_*)`→CURLOPT_HTTP_VERSION。
  - `置请求头(文本型 数组)`→curl_slist_append 组链 + CURLOPT_HTTPHEADER。
  - `置缓冲区大小(整数)`→CURLOPT_BUFFERSIZE。
  - `置代理(文本 用户名 密码)`→CURLOPT_PROXY(+CURLOPT_PROXYUSERPWD)。
  - `置登录用户名(用户名 密码)`→CURLOPT_USERPWD。
  - `置验证SSL证书(逻辑 [, 逻辑])`→CURLOPT_SSL_VERIFYPEER(+VERIFYHOST)。
  - `置重定向(逻辑 [, 最大次数 默认5])`→CURLOPT_FOLLOWLOCATION(+MAXREDIRS)。
  - `置TCP长连接(开启逻辑 [, 超时秒 默认60])`→CURLOPT_TCP_KEEPALIVE(+KEEPIDLE)。
  - `置超时(连接秒 请求秒)`→CURLOPT_CONNECTTIMEOUT+CURLOPT_TIMEOUT（毫秒版 `置超时毫秒`）。
  - `置传输编码(文本 可空)`→CURLOPT_ACCEPT_ENCODING（留空=关闭 curl 自动解压）。
  - `置引用页(文本)`→CURLOPT_REFERER；`置UserAgent(文本)`→CURLOPT_USERAGENT。
- **`zyCurl` 全局命令**（`模块\zyCurl\代码\__HIDDEN_TEMP_MOD__.static.e.txt`）：`CURL取错误文本(整数 错误码)`→curl_easy_strerror；`CURL_检查DLL文件()`；`CURL初始化()`/`CURL卸载()`。
- **`全局_是否加载CURL`（整数型）**：定义在 `模块\zyCurl\全局变量.e.txt`，注释"指示当前程序的CURL的DLL是否已加载并且初始化"。Curl 类 `_初始化` 判断 `全局_是否加载CURL ＝ 1` 才建句柄。⚠️ 本模块自身 `全局变量.e.txt` 里只有一个从未被引用的 `全局_检查CURL`（见第六节 bug）。
- **`调用子程序(程序地址, 返回值[参考可空], 参数1[可空], 参数2..)`**：易语言系统核心支持库命令，按地址动态调用用户回调子程序。第二槽=被调子程序返回值接收位（这里恒留空/传静态变量），从第三槽起为回调实参。
- **gzip**：`网页_GZIP解压(字节集)`（通用模块）调用外部 `gzip.dll`（`InitDecompression/CreateDecompression(3)/Decompress/DestroyDecompression`）。`#GZIP` 是二进制资源常量（gzip.dll 本体），WinHTTP/WinInet 类 `_初始化` 会把它落地到运行目录。

## 编码约定速查（三条路线各自的转换点）

| 数据 | Curl 路线 | WinHTTP 路线 | WinInet 路线 |
|---|---|---|---|
| 网址 | 文档要求 **UTF-8** 文本，直接 `置URL(完整网址)`（curl_http 内部再处理） | `M2W(文本,#CP_ACP)` GBK→UTF-16 后传 W-版 API | 直接 ANSI（A 版 API），GBK 文本原样传 |
| 请求头 | `网页_构建协议头` 产 GBK 文本 → `分割文本` → `置请求头(GBK文本数组)`（curl_http 内部编码） | `M2W(附加协议头,#CP_ACP)`→`W2P`→`WinHttpSendRequest` | GBK 文本直接 `HttpSendRequestA(附加协议头, 取文本长度)` |
| 响应头 | `CURL类.取响应头()` 取回（GBK 文本） | `WinHttpQueryHeaders`→UTF-16 字节集→`W2M(...,#CP_ACP)`→GBK | `HttpQueryInfoA(...,22,GBK缓冲)`→GBK |
| 响应体 | 原始字节集，按魔术字节判 gzip | 原始字节集 | 原始字节集 |
| #CP_ACP | — | ANSI 代码页（中文系统=936/GBK）用于 M2W/W2M | — |
- `M2W(文本,代码页)`=`MultiByteToWideChar`（GBK→UTF-16），返回 UTF-16 字节集（长度 2n+1）。
- `W2M(UTF-16字节集,代码页)`=`WideCharToMultiByte`（UTF-16→GBK），返回文本。
- `W2P(UTF-16字节集)`=把字节集拷到堆并返回其指针（`lstrcpyn_bytes2pointer`），用于给 API 传 LPWSTR/LPVOID。
- `P2W(整数指针, 长度)`=指针→字节集。

### 公开成员命令（逐字）

1. `_初始化()` 返回：无。
   - 若 `全局_是否加载CURL ＝ 1`：`CURL类.创建()`；`CURL ＝ CURL类.取句柄()`。否则 `CURL ＝ 0`。
   - `是否初始使用系统默认COOKIE ＝ 假`；`是否自动更新COOKIE ＝ 真`；`每次接收字节 ＝ #HTTP配置_默认每次接收数据长度`（512）。
2. `_销毁()` 返回：无。
   - `如果真 CURL ≤ 0 → 返回`。其余 curl_easy_cleanup / slist_free / global_cleanup **全部被注释**，实际不做任何释放。⚠️（见第六节）
3. `设置每次接收长度(接收长度:整数型)` 返回：无。语义注释"字节"。
   - `如果 接收长度 ≤ 0 → 接收长度 = #HTTP配置_默认每次接收数据长度`；`每次接收字节 = 接收长度`。
4. `设置COOKIE(COOKIE:文本型[可空], 是否使用默认COOKIE:逻辑型[可空], 是否自动更新COOKIE_参数:逻辑型[可空])` 返回：无。
   - `如果真 CURL ≤ 0 → 返回`（⚠️：Curl 未加载时此设置静默失效，见 bug）。
   - `是否自动更新COOKIE = 选择(是否为空(是否自动更新COOKIE_参数), 真, 是否自动更新COOKIE_参数)`（省略=真）。
   - `是否初始使用系统默认COOKIE = 选择(是否为空(是否使用默认COOKIE), 假, 是否使用默认COOKIE)`（省略=假）。
   - `如果 是否初始使用系统默认COOKIE = 假`（不用 IE 默认）：`当前是否为自定义设置COOKIE = 真`；`提交Cookies = COOKIE`。`否则`：`当前是否为自定义设置COOKIE = 假`（**不改 提交Cookies**，保留旧值）。
5. `设置DNS服务器(服务器1:文本型[可空], 服务器2:文本型[可空])` 返回：无。→ 赋 `设置DNS服务器1/2`（当前无下游消费者，见 bug）。
6. `获取当前提交的COOKIE()` 返回：文本型 → `返回(上次提交Cookies)`。
7. `获取当前返回的COOKIE()` 返回：文本型 → `返回(返回Cookies)`。
8. `设置CURL句柄(CURL2:整数型)` 返回：无。→ `CURL = CURL2`；`CURL类.置句柄(CURL2)`。
9. `设置共享的DNS缓存(SHARE句柄:整数型[可空])` 返回：无。→ 空实现（`如果真 CURL≤0 返回` 后全被注释），stub。
10. `SetOption(Option:整数型, Value:通用型)` 返回：整数型。→ `如果真 CURL≤0 返回 0`；主体注释掉，**恒返回 0**（dead）。
11. `SetOption_int(Option:整数型, Value:整数型)` 返回：整数型。→ `如果真 CURL≤0 返回 0`；`返回(CURL类.置选项(Option, Value))`（直传不取指针）。
12. `模仿(脚本名称:文本型, 使用默认请求头:逻辑型[可空])` 返回：整数型。→ `返回(CURL类.模仿(脚本名称, 使用默认请求头))`。脚本名称 ∈ {chrome99,chrome100,chrome101,chrome104,chrome107,chrome99_android,edge99,edge101,safari15_3,safari15_5}。
13. `访问网页_cURL(...) 字节型=字节集` — 主命令，全流程见下。

### `访问网页_cURL` 全流程（逐字签名 + 顺序）

返回类型：字节集。参数表（序号/名/类型/可空/默认语义）：

| # | 名 | 类型 | 可空 | 语义 |
|---|---|---|---|---|
|1|`完整网址`|文本型|否|提供 UTF8 编码|
|2|`访问方式`|文本型|是|默认 GET，也可 POST|
|3|`回调子程序`|整数型|是|进度回调地址；参数：1整数 clientp、2~5 双精度 dltotal/dlnow/ultotal/ulnow|
|4|`提交信息`|字节集|是|POST 体|
|5|`超时`|整数型|是|单位秒|
|6|`附加协议头`|文本型|是||
|7|`返回头`|文本型|**参考** 是|出参：响应头|
|8|`禁止重定向`|逻辑型|是|默认假|
|9|`网站登录用户名`|文本型|是||
|10|`网站登录密码`|文本型|是||
|11|`代理地址`|文本型|是|0.0.0.0:0000 格式；`*`=系统代理|
|12|`代理用户名`|文本型|是||
|13|`代理密码`|文本型|是||
|14|`是否采用Gzip`|逻辑型|是|请求 gzip（注意勿与请求头 accept-encoding 冲突）|
|15|`失败日志`|文本型|**参考** 是|出参：错误原因|
|16|`代理连接失败自动处理`|逻辑型|是|代理连接失败自动去代理重试|
|17|`模拟浏览器TSL`|文本型|是|默认 chrome107（curl-impersonate target）|
|18|`回调用户参数`|整数型|是|回调第 1 参数（clientp）|
|19|`回调次数`|整数型|是|重试计数（内部递归用）|

执行顺序：

1. **守卫**：`如果真 CURL ≤ 0 → 返回 ({ })`（空字节集）。
2. **默认值规整**（就地改写参数）：
   - `是否采用Gzip = 选择(是否为空, 真, 是否采用Gzip)`（省略=真）。
   - `超时 = 选择(是否为空, 60, 超时)`。
   - `禁止重定向 = 选择(是否为空, 假, 禁止重定向)`。
   - `访问方式 = 到大写(选择(是否为空(访问方式) 或 访问方式="", "GET", 访问方式))`。⚠️ 与 WinHTTP/WinInet 类不同：本类默认恒为 GET（不看 `提交信息`）。
   - `代理连接失败自动处理 = 选择(是否为空, 假, 代理连接失败自动处理)`。
   - （注释掉的 `调子程序` 默认行忽略。）
3. **建/重取句柄**：`CURL类.创建()`（重建 easy 句柄）；`CURL类.置URL(完整网址)`（UTF8 网址）。
4. **进度回调**：`如果真 是否为空(回调子程序)=假 且 到整数(回调子程序)≠0 → CURL类.置进度回调2(回调子程序, 回调用户参数)`。→ 设 CURLOPT_XFERINFO/PROGRESS 回调；回调在传输过程中被 libcurl 反复调用，透传 clientp=回调用户参数、dltotal/dlnow/ultotal/ulnow。
5. **POST**：`如果真 是否为空(提交信息)=假 且 访问方式="POST" → CURL类.置POST数据字节集(提交信息); CURL类.置POST(真)`。
6. **IE 默认 Cookie**：`如果真 是否初始使用系统默认COOKIE` 且 `提交Cookies="" 且 当前是否为自定义设置COOKIE=假` → `提交Cookies = 网页_取Cookie_内部(网页_取域名(完整网址), , 文本是否存在(完整网址,"https://"))`。即取 IE/系统 Cookie 容器里该域名的全部 Cookie（见"特别标出"）。
7. **impersonate**：`如果 模拟浏览器TSL≠"" → 模仿(模拟浏览器TSL, 假)`；否则 `模仿("chrome107", 假)`。**default_headers=假**（不让 impersonate 覆盖后续自定义请求头）。
8. **HTTP 版本**：`CURL类.置协议版本(#CURL_HTTP_VERSION_1_1)`。
9. **请求头构建**：`附加协议头 = 网页_构建协议头(附加协议头, 完整网址, 提交Cookies, 访问方式="POST", 是否采用Gzip, 取字节集长度(提交信息))`（GBK 文本，补全 Accept/Host/Connection/User-Agent/Accept-Language/Cookie/Accept-Encoding: gzip/Content-Type/Content-Length，见第四节 helper）。`header_arr = 分割文本(附加协议头, #换行符)`；`CURL类.置请求头(header_arr)`（→ CURLOPT_HTTPHEADER 链表）。`CURL类.置缓冲区大小(每次接收字节)`（CURLOPT_BUFFERSIZE）。
10. **代理**：`如果真 代理地址="*" → 代理地址 = 网页_取系统代理EX()`。`如果 代理地址≠"" → CURL类.置代理("http://"+代理地址, 代理用户名, 代理密码)`；否则 `CURL类.置代理("", "", "")`。（**强制加 `http://` 前缀**。）
11. **站点登录**：`如果 网站登录用户名≠"" → CURL类.置登录用户名(网站登录用户名, 网站登录密码)`；否则 `置登录用户名("","")`（CURLOPT_USERPWD）。
12. **SSL/重定向/长连接**：`置验证SSL证书(假)`（不校验）；`置重定向(取反(禁止重定向))`（CURLOPT_FOLLOWLOCATION=禁止重定向?0:1）；`置TCP长连接(真, 超时)`（KEEPALIVE 开，时长=超时秒）。
13. **超时/编码/信号**：`置超时(超时, 超时)`（CONNECT+TIMEOUT 同秒）；`置传输编码("")`（**关闭 curl 自动解压**）；`置选项(#CURLOPT_无信号, 1)`（CURLOPT_NOSIGNAL=1，多线程必需）。
14. **执行**：`res = CURL类.执行()`（curl_easy_perform，返回 CURLE_ 码）。
15. **失败处理 / 代理自动重试**（`如果真 res ≠ 0`）：
    - `失败日志 = CURL取错误文本(res)`（出参填充，curl_easy_strerror）。
    - `如果真 代理连接失败自动处理`：`如果真 res=7 或 res=35 或 res=28`（代理连不上/SSL无法连接/超时）：`如果真 回调次数 < 3`（**最大重试 3 次**）：`如果真 取反(回调次数=0 且 代理地址="")`（即"首次且本就没用代理"时**不重试**）→ `回调次数 += 1`；**递归** `返回(访问网页_cURL(...同参数..., 代理地址="" ,代理用户名="", 代理密码="", ...其余同..., 回调次数))`——**取消代理**重发（第 11/12/13 参传空串），其余参数原样，回调次数带入下一层。
    - `如果真 是否为调试版()` 且 `res≠0` → `调试输出("CURL提交失败:", 失败日志)`。
16. **取响应头 + Cookie 合并**（无论成功失败都执行）：
    - `返回头 = CURL类.取响应头()`（出参填充）。
    - `上次提交Cookies = 提交Cookies`。
    - `返回Cookies = 网页_提取返回头COOKIE(返回头)`。
    - `如果真 提交Cookies≠"" 且 是否自动更新COOKIE → 返回Cookies = 网页_Cookie合并更新_内部(提交Cookies, 返回Cookies)`。
17. **取数据 + 销毁句柄**：`ret = CURL类.取响应数据()`（响应体字节集）；`CURL类.销毁()`（curl_easy_cleanup）。

#### 特别标出（Cookie 三点）

- **三参数优先级**（`设置COOKIE`）：
  - `是否使用默认COOKIE`（=真→`是否初始使用系统默认COOKIE=真`）优先级最高：为真时走 IE 默认 Cookie 分支，`设置COOKIE` 的第 1 参 `COOKIE` 被忽略（不再写入 `提交Cookies`，且把 `当前是否为自定义设置COOKIE` 置假）。
  - 为假/省略→ `当前是否为自定义设置COOKIE=真` 且 `提交Cookies = COOKIE`（自定义，优先级次之；即使 COOKIE 传空串也算"自定义空 Cookie"，`访问网页_cURL` 里因 `当前是否为自定义设置COOKIE=真` 而**不会**去取 IE 默认）。
  - `是否自动更新COOKIE_参数` 与前两者独立，只控制返回 Cookie 是否与提交 Cookie 合并（省略=真）。
- **系统默认(IE)Cookie 怎么取**：`网页_取Cookie_内部(域名, 名称="", 是否HTTPS)`（定义于 `WinHTTP专用.static.e.txt`，被三条路线共用）：
  - 拼 `网址 = (是否HTTPS?"https://":"http://") + 域名`；域名来自 `网页_取域名(完整网址)`（去协议、去路径、去端口）。
  - 读两条缓冲各 3000 字节：`InternetGetCookieA(网址, 字符(0), 读取内容, 3000)` 与 `InternetGetCookieExA(网址, 字符(0), 读取内容1, 3000, 8192, 0)`（flag **8192=0x2000=INTERNET_COOKIE_HTTPONLY**，多读 HttpOnly Cookie）。
  - `网页_Cookie合并更新_内部(读取内容, 读取内容1)` 合并两者（⚠️ 该合并返回值未被接收，只靠"旧Cookie"参考参数被写回——见 bug）。
  - 若传了 `Cookie名称` 再 `网页_取单条Cookie` 过滤（访问时传空=返回全部）。
  - `是否HTTPS` 由 `文本是否存在(完整网址,"https://")` 决定。
- **返回 Cookie 如何合并**：`返回Cookies = 网页_提取返回头COOKIE(返回头)`（逐行扫 `Set-Cookie:` 提取 `名=值`，`;` 结尾拼接）。若本次有提交 Cookie 且开了自动更新：`网页_Cookie合并更新_内部(提交Cookies, 返回Cookies)` 以"新（返回）覆盖旧（提交）同名、旧有而新无者保留、剔除 `=deleted/=delete`、去重"的规则合并（见第四节）。合并结果写回 `返回Cookies`。

### 共享 helper（`网页_构建协议头` 精确行为，三条路线都调用）

`网页_构建协议头(附加协议头, 完整网址, 提交COOKIE, 是否为POST, 是否采用GZIP, 提交POST字节集长度[可空默认0])` → 文本型（GBK）：
- 末尾若无 `#换行符` 补一个。
- 若出现 `Referer:***`（大小写不敏感）→ 删除该行（亚马逊特例：`***` 表示不提交 Referer）。
- 逐个缺失补默认：无 `Accept:` → `Accept: */*`；无 `Host:` → `Host: ` + `网页_取域名(完整网址)`；无 `Connection:` → `Connection: Keep-Alive`；无 `User-Agent:` → `#HTTP配置_默认浏览器UA`；无 `Accept-Language:` → `Accept-Language: zh-CN`。
- `提交COOKIE≠"" 且 无 Cookie:` → 追加 `Cookie: ` + 提交COOKIE。
- `是否采用GZIP 且 无 Accept-Encoding:` → 追加 `Accept-Encoding: gzip`。
- `是否为POST`：无 `Content-Type:` → 追加 `Content-Type: application/x-www-form-urlencoded`；`提交POST字节集长度>0 且 无 Content-Length:` → 追加 `Content-Length: <长度>`。

`网页_取系统代理EX()` → 文本型：先读注册表 `HKLM\SYSTEM\ControlSet001\Services\NlaSvc\Parameters\Internet\ManualProxies\`（有 `http=`/`https=` 取中间值），无果再判 `HKCU\...\Internet Settings\ProxyEnable=1` 后读 `ProxyServer`（有 http=/https= 取中间，否则整串）。

`计算每次接收块大小(连接耗时ms)`：≤50→20240；≤500→10240；≤1000(且>300)→5120；≤2000(>1000)→2048；≤5000(>2000)→1024；否则→128。（判断链有重叠：≤300~500 区间落入第 2 支返回 10240。）

`网页_GZIP解压(字节集)`：`InitDecompression(); CreateDecompression(context,3)`；循环 `取字节集中间(inData, 解压位置+1, 8192)`→`Decompress(context, in, inLength, buffer(8192), 8192, inUsed, outUsed)`；`outUsed≠0` 累加 `取字节集左边(buffer,outUsed)`，`解压位置+=inUsed`；`循环判断尾(hResult=0)`；`DestroyDecompression(context)`；返回累加字节集。

`网页_提取返回头COOKIE(返回头)`：按 `#换行符`（退化 char(10)/char(13)）分行；每行含 `Set-Cookie`（不区分大小写）→ 有 `;` 取 `Set-Cookie:`..`;` 中间，否则取 `Set-Cookie:` 右边；删首尾空；过滤空/`-`/结尾`=-`；`结果 += 值 + ";"`。

`网页_Cookie合并更新_内部(旧Cookie[参考], 新Cookie)`：两者删全部空 → 按 `;` 分割；遍历旧组，凡旧名在新组不存在的项加入新组；丢弃 `=deleted`/`=delete` 项；用 `文本_去重复文本(";" )` 去重；结果写回参考参数 `旧Cookie` 并 `返回(旧Cookie)`。

## 六、源码里的坑 / bug 与行为差异（逐条）

1. **全局变量名对不上（跨模块耦合）**：本模块 `全局变量.e.txt` 只声明了从未被使用的 `全局_检查CURL(文本型)`；Curl 类 `_初始化` 实际判 `全局_是否加载CURL(整数型)`，该变量属于外部 zyCurl 模块。若 zyCurl 未加载/未初始化，`CURL=0`，`访问网页_cURL` 立即返回空字节集，其余 Curl 方法静默无效。迁移需明确"CURL 已加载"标志来源。
2. **Curl `_销毁` 什么都不做**：`curl_easy_cleanup/curl_slist_free_all/curl_global_cleanup` 全被注释，只在 `CURL≤0` 时提前返回。真正的句柄释放靠 `访问网页_cURL` 末尾 `CURL类.销毁()`。对象若在访问完成后销毁则无额外泄漏；但若创建对象却从未访问，`_初始化` 建的句柄不会释放（轻泄漏）。
3. **Curl 成员 `CURL` 句柄快照失效**：`访问网页_cURL` 每次 `CURL类.创建()` 重建 easy 句柄、末尾 `CURL类.销毁()` 释放，但整型成员 `CURL` 仍是首次 `_初始化` 时的旧值且 >0，`≤0` 守卫形同虚设；`设置CURL句柄` 可外部覆盖但同样不同步真实句柄。C++ 版应改为按调用作用域管理句柄。
4. **Curl `SetOption` 恒返回 0**（主体注释），`设置共享的DNS缓存` 空实现（文档注释误抄"设置CURL使用的句柄"），`设置DNS服务器` 写入的成员 `设置DNS服务器1/2` 无任何下游使用（旧 CURLOPT_DNS_SERVERS 代码被注释，注明"DLL 需 7.24+ 才支持"）。这三者是死代码。
5. **Curl `设置COOKIE` 有 `CURL≤0 返回` 守卫，WinHTTP/WinInet 版无**：Curl 未加载时设 Cookie 静默失败，其它路线永远生效——行为不一致。
6. **Curl `访问方式` 默认值与 WinHTTP/WinInet 类不同**：Curl 类空 `访问方式` 恒默认 `"GET"`（不看 `提交信息`），而 WinHTTP/WinInet 类默认 `选择(提交信息={}, "GET","POST")`。直接调类方法传空方式+POST 体时，Curl 不会切 POST（`置POST数据字节集`/`置POST` 分支要求 `访问方式="POST"`）。全局 `网页_访问_Curl` 预先算了 POST 并显式传入，掩盖了此差异。迁移需逐条保留各自默认。
7. **Curl Gzip 与 `置传输编码("")`**：`是否采用Gzip` 只决定请求头是否带 `Accept-Encoding: gzip`；curl 自身解压被关闭（`置传输编码("")`），改由魔术字节 `{31,139,8}` 判定后用 gzip.dll 手动解压。若服务器用非 gzip 魔术头/分块返回压缩体则不解压。
8. **Curl 代理强制 `http://` 前缀**：`置代理("http://"+代理地址,...)`，无法表达 socks4/socks5；文档虽称"原则上支持其他类型"但代码写死 http。
9. **Curl 代理自动重试的守卫反直觉**：`取反(回调次数=0 且 代理地址="")` —— 只有"已在重试(次数>0) 或 本次确实用了代理"才会去代理重发；首次且本就无代理时不重试。重试上限 3，递归传 `代理地址=""/代理用户名=""/代理密码=""` 实现"取消代理"。`回调次数` 参数语义被复用为重试计数器（与"回调用户参数"分离，但对调用者易混淆）。重试递归内每层都会重新 `CURL类.创建()/销毁()`、重设 impersonate 与请求头。
10. **三个全局命令的 `返回COOKIE` 缺 `参考`**：`网页_访问_Curl/WinHTTP/WinInet` 声明 `返回COOKIE: 文本型, 可空`（非参考），却在末尾 `返回COOKIE = HTTP网页访问.获取当前返回的COOKIE()`。赋值只改局部副本，**调用者拿不到返回 Cookie**。若要照修需与用户确认（会改变现有可见签名行为）。
11. **WinHTTP `WinHttpOpenRequest` 失败判据用 `<0`**：应 `≤0`（API 失败返回 NULL=0），0 句柄漏判会继续往下走。`会话句柄≤0`/`连接句柄≤0` 用的是正确的 `≤0`。
12. **WinHTTP 句柄泄漏 / 关闭顺序**：中途错误 `返回({ })` 时（除"发送 5 次失败"关请求句柄外）请求/连接/会话句柄不立即关闭，仅靠下次调用开头的 `内部销毁方法()` 或 `_销毁` 回收；`内部销毁方法` 关闭顺序为 连接→会话→请求（应先请求后连接后会话，顺序颠倒）。WinInet 版 `内部销毁方法` 顺序是 会话→连接→请求（也不同）。C++ 应统一按 请求→连接→会话 逆序关闭并在每条出口 RAII 释放。
13. **WinHTTP 响应头缓冲固定 50000 字节宽字符**：`取空白字节集(50000)`，头超过 ~25000 个 UTF-16 单元被截断（Content-Length/Set-Cookie 若靠后可能丢）。WinInet 更严：`取空白文本(5000)`（仅 5000 字节 ANSI）。
14. **WinHTTP 建立会话回调异常传参**：唯一一次 `调用子程序(addr,, 返回_整数型, #HTTP状态_建立会话, 0,0,0,0)` 把静态局部 `返回_整数型` 放进第 3 槽，其余回调都用空槽——迁移时该特殊槽多半可忽略（等价噪声参数）。
15. **WinHTTP `请求标记` 变量复用**：既作 POST 内容长度（SendRequest）又作 `WinHttpReadData` 实际读出字节数（回写），语义在函数内切换；发送成功后其值被读循环覆写，Content-Length 另存于 `返回数据长度`。移植时应拆成两个变量。
16. **WinHTTP `是否采用Gzip=真` 会无条件尝试解压**：`如果真 是否采用Gzip 或 Content-Encoding 含 gzip` → 解压；若服务器没真压缩而 `是否采用Gzip` 默认真（参数省略即真），`网页_GZIP解压` 失败返回空 → 因 `如果真 局_GZIP解压数据≠{}` 判空而回退返回原始 `返回信息`（此处尚可），但语义上"默认要 gzip"会多发 `Accept-Encoding: gzip`（`网页_构建协议头`）。
17. **WinInet UA 前缀冗余**：`局_User_Agent = "User-Agent: " + 值` 整串传给 `InternetOpenA` 的 lpszAgent（应为纯 UA 值，不带 `User-Agent: ` 头名）；当走默认分支时 `#HTTP配置_默认浏览器UA` 本身也含 `User-Agent: ` 前缀——同样问题。会导致发出不合法 UA。WinHTTP 分支把含前缀串 M2W 后当 UA 传 `WinHttpOpen`，也有同样前缀问题。
18. **WinInet `InternetOpenA` accessType 语义混乱**：无代理时传字面量 `1`（=PRECONFIG）却随后又用 `INTERNET_OPTION_PROXY` 强制设 DIRECT；有代理时传 `3`(PROXY)+`"http="+代理地址`。两处代理机制重叠。
19. **WinInet `请求句柄=0` 判空放在设代理凭据之后**：若 HttpOpenRequestA 失败(0)，仍先对 0 句柄 `InternetSetOption_str(0,...)` 设代理凭据（无害但错误顺序），之后才判空返回。
20. **WinInet 手动 301 递归是坏的**：`局_重定向地址 = 返回头 + 网页_取页面地址(完整网址)` 算出后**从不使用**；递归调 `访问网页_WinInet` 传的是**原 `完整网址`**（未替换成 Location），且传入的 `超时` 已是"×1000 后的毫秒"，递归里又 ×1000 → 超时被平方放大。禁止重定向时本不该走这里，但 `INTERNET_FLAG_NO_AUTO_REDIRECT` + 未清标志的组合下 301 仍可能被查询到。整体重定向逻辑应重写：真正解析 Location 并对新 URL 递归，且不要重复缩放超时。
21. **WinInet Cookie 合并条件不同**：合并只看 `是否自动更新COOKIE`，不要求 `提交Cookies≠""`；而 Curl/WinHTTP 两者都要求。导致 WinInet 在无提交 Cookie 时也会调用合并（`网页_Cookie合并更新_内部("" , 返回Cookies)`）。
22. **WinInet/WinHTTP `网页_取Cookie_内部` 合并结果未接收**：内部 `网页_Cookie合并更新_内部(读取内容, 读取内容1)` 靠参考参数写回 `读取内容`，函数体最后 `返回(读取内容)` 用的是被写回的 `读取内容`——逻辑成立但隐蔽；若"参考"语义在移植中丢失，IE 默认 Cookie 的普通+HttpOnly 两路合并会丢一半。
23. **`HTTP状态_错误_接收不到数据(11)` 与 `HTTP状态_处理完成(11)` 同值**：回调接收方无法仅凭状态码区分"正常完成"与"完全没收到数据"（两者都 11），需靠参数（数据指针/是否收到过字节）区分。WinInet 用 `局_页面内容={}` 判空才发错误回调，否则正常路径也是 11。
24. **`计算每次接收块大小` 判断链区间重叠/空洞**：第 3 支 `≤1000 且 >300`（与第 2 支 `≤500` 重叠 300~500 段，因先判第 2 支故 50~500 返回 10240）；1000~? 边界处 `>1000 且 ≤2000` 才 2048。区间不整齐，移植时按"先命中先返回"的短路顺序照抄即可，勿重排。
25. **`是否初始使用系统默认COOKIE` 与 `当前是否为自定义设置COOKIE` 语义纠缠**：`设置COOKIE(默认参数)` 走"用 IE 默认"分支时只把 `当前是否为自定义设置COOKIE` 置假、不清 `提交Cookies`；因此若之前设过自定义 Cookie，切到"默认"分支后 `提交Cookies` 仍非空，`访问网页_*` 里 `提交Cookies=""` 判据不成立→**不会**去取 IE 默认 Cookie。即"从自定义切回默认"需要 `提交Cookies` 恰为空才生效，属隐性状态依赖。
26. **`内部销毁方法`/`取响应代码` 等未使用**：Curl 类未定义 `取响应代码`（响应 HTTP 码未回传，只回字节集）；`判断响应头是否有效/取响应头代码/网页_取返回协议代码` 在访问类里未被调用（其它模块用）。
27. **调试输出与落地副作用**：WinHTTP/WinInet `_初始化` 会在运行目录写 `gzip.dll`（不存在时），Curl 路线不写（Curl 自带或走 zyCurl）；`调试输出("CURL请求头"/"请求协议头"/"CURL提交失败")` 在发布版被系统清空但调试版会刷屏——迁移时可去除或降级为日志开关。
