# zyJson2.51 对照测试（差分验收）

目的：证明 `创想软件支持库 3.4.0` 的 `Json2` 类与原 `zyJson2.51.e` 模块**输入输出一致**。
做法是差分而不是断言：同一份代码跑两遍，一遍走原模块、一遍走新库，比两份落盘结果。
所以这份源码里**不写期望值**，期望值就是原模块自己的行为。

- 代码：`对照源码.txt`（整段粘进 IDE 的代码表，两个工程贴同一份）
- 比对：`比对结果.bat`
- C++ 侧的语义断言（离线宿主）已经全绿，见 `libs\创想软件支持库\README.md` 的「命令覆盖测试」；
  本目录只负责真机（易语言 IDE）这一半。

## 一、搭两个工程

两个工程都必须**只**引用一侧的 `Json2`，否则同名会互相抢占（同名的库命令/类型，IDE 只会认一个，
错的那侧被静默替换，对照就变成自己跟自己比，结果全绿但毫无意义）。

### 工程甲 · 基线 = 原模块

1. 新建 Windows 程序，支持库只勾 `系统核心`（`krnln`），**不要勾创想软件支持库**。
2. 把 `E:\dev\a我的程序项目\☆模块\zyJson2.51.e` 作为外部模块加入工程（模块→添加现有模块）。
3. 窗体上放一个按钮，控件名必须叫 `按钮1`。
4. 打开程序集代码表，整段粘贴 `对照源码.txt` 分隔线以下的内容（从 `.版本 2` 开始）。
   粘完确认代码表里没有 `.支持库 spec`／`iext` 之类引用；有就删掉。
5. 编译运行 → 点按钮 → EXE 目录出 `zydiff_text.txt` 与 `zydiff_wide.bin`。
6. 把这两个文件放进 `对照测试\res\A\`（自己建目录；目录名保持 ASCII，bat 里不能带中文）。

### 工程乙 · 新版 = 创想软件支持库

1. 同样新建工程，支持库勾 `创想软件支持库`（版本 3.4.0，见「三、产物确认」），**不要引用 zyJson 模块**。
2. 同一个窗体、同一份代码粘贴、同样放 `按钮1`。
3. 编译运行 → 点按钮 → 把两个产物放进 `对照测试\res\B\`。

> 两边的 `按钮1` 上不要写任何别的代码；两边都用同一个 `取运行目录()`，产物落在各自 EXE 目录。

## 二、比对

```
cd libs\zyJson支持库\对照测试
cmd /c 比对结果.bat
```

脚本做两件事：`fc` 逐行比 `zydiff_text.txt`（同时把差异抄到 `diff_text.txt`），
`fc /b` 逐字节比 `zydiff_wide.bin`（差异抄到 `diff_wide.txt`）。

判读规则：

1. 差异行左边的标签（如 `1.11 u 默认解码`、`7.T4 写入格式`）就是用例名，对着下面两张表看。
2. **表外的差异一律按 bug 处理**，把那一行的甲/乙两侧原文发我，我按原模块改库。
3. `zydiff_wide.bin` 的偏移不直接可读，但 `zydiff_text.txt` 里每个 `记宽一行` 都同步写了 `xxx.长度`，
   长度对不上就说明是哪个用例先出的问题；长度一致而字节不一致，才需要看 bin 的偏移。

## 三、产物确认（避免跑在旧 .fne 上）

工程乙跑之前，先确认装载的是新库：在按钮代码里临时加一行

```
调试输出 (取库版本标识 ())
```

期望形如 `3.4.0-<链接日期 时间>-395-...`。命令总数必须是 **395**（旧版是 279/280）。
如果显示的还是旧版本号，说明 IDE 用的是 `lib\cxsoft.fne` 的旧副本或被 `.fne.new` 暂存挡住了：
关掉 IDE → 跑 `libs\创想软件支持库\build.bat`（或 `install_to_epl.bat`）→ 重开 IDE 再看一次。

当前状态（2026-10-13）：`D:\e5.5\lib\cxsoft.fne` = `out\cxsoft.fne`（MD5 `3168f5e6860fcb3c55a7a4dea3a1ef09`），
静态库已落 `D:\e5.5\static_lib\cxsoft_static.lib`；`D:\e5.5NewExui\lib\` **还没有**这份 .fne，
如果工程乙要在那个 IDE 里编，先跑 `install_to_epl.bat`（脚本会自动选根目录）。

## 四、已知会不同 / 需要你拍板的项

这些是我在 C++ 重写时**主动做过解释选择**的地方，规格里记在 `libs\zyJson支持库\spec-core.md` §9（T-1…T-10）。
差分如果落在这些项上，不要当 bug，直接按「要哪种」告诉我：

| 项 | 用例标签 | 我在库里怎么做 | 需要你确认 |
| --- | --- | --- | --- |
| T-1 | `7.T1 *` | 数值串的解析按 `strtod` 口径（`1e400`→inf、`.5`→0.5、`+2`→2、`1.2.3`→1.2 部分解析、`"  7 "` 吞前导空白） | 原模块走易语言 `到数值`，若两者不一致，我以原模块为准重标 |
| T-2 | `7.T2 带空格键` | 引号内空格保留（`{"a b":1}` 键就是 `a b`） | 原模块若吞空格（R1），要不要照抄 |
| T-3 | `7.T3 *` | 路径 `[n]` 的 n 按十进制解析；`取整数` 对字符串用十进制转换（`0x10`→0，`abc`→0） | 原模块用 `StrToInt`（返回 BOOL 的疑点），若它给出别的值我照抄 |
| T-4 | `7.T4 写入格式`、`7.T4 复制后格式` | 程序写入的 double 用 `%.15g` 同族格式化（含 `-0` 保号、1e21 之类科学计数阈值、尾零截断） | 易语言 `到文本(双精度)` 的默认位数/阈值要和它逐字符一致 |
| T-5 | `7.T5 *` | 返回文本不带尾部 0 字节 | 原模块若多一个 0 字节，历史代码可能按长度判空，需确认 |
| T-6 | `7.T6 *` | `_wtoi64` 口径：越界饱和、`取整数` 只取低 32 位 | 原模块如给出别的（0/-1）以它为准 |
| T-7 | `7.T7 u0000` | `\u0000` 存进去即终止（与 WideChar 口径一致） | 同上，看甲侧长度 |
| T-8/T-9 | 段5 末尾可选块 | 排序：非稳定快排（三数取中 + 挖洞法，`>=0`/`<=0` 停）照抄；`参数_算法` 原版写死 0 | 要跑就按注释补 `比较函数` 再对一次 |
| T-10 | `7.T10 两次置文本W` | `置文本W` 判终止符用长度而非 `取字节集左边`，连续两次结果正确 | 原版这里疑点（H-6），若它第二次丢字符，属原版 bug |

另有两项**编码口径的例外**（不是 bug，是与原模块一致的选择）：

- `Json2` 族的 `文本型` = GBK(cp936)，`W` 后缀 = UTF-16LE 字节集（可带 `{0,0}`），`*UTF8` = UTF-8；
  本库其它命令一律 UTF-8。见 `README.md` 的「JSON（3.4）」。
- 代理对（`😀`，用例 `1.13/1.14`）落到 GBK 是无效字符，两版都可能出 `?`，只要两边一致即可。

## 五、这份对照没覆盖的东西

| 项 | 原因 | 兜底 |
| --- | --- | --- |
| `排序` / `排序W` 回调 | 参数是 `子程序指针`，两边必须有同名回调子程序才能比 | 段5 末尾给了可选块与 `比较函数` 模板 |
| `置文本数组UTF8` / `置数值数组UTF8` / `置整数数组UTF8` / `置逻辑数组UTF8` | 入参要求数组元素本身是 UTF-8 字节流的「文本型」，纯 krnln 造不出来（不引第三方转换） | 离线宿主 `host_json` 已按构造字节覆盖这四条；真机要测就用你的 HTTP 库拿一段 UTF-8 文本数组喂进去 |
| 网络/文件 IO | 与本族无关 | — |

`libs\创想软件支持库\host_json.cpp` 已把 115 条成员命令**逐条真调用并断言语义**（未覆盖 0 条），
所以本对照工程的重点是：IDE 侧的类型/参数编组是否接得上、GBK 与字节集口径、以及上面那张 T 表。
