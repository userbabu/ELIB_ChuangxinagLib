## 记法约定（A 节）

- 参数一律用源码 `.参数` 行原文（代码块内），**属性字段完全按源码写**：`可空` / `参考` / `数组` / `参考 可空` / `参考 可空 数组` / `参考 数组`；属性字段为空（源码写成 `, 文本型, , 说明`）表示**不可空且无数组/参考**。
- 「可空默认」= 从方法体内 `选择 (是否为空 (...), 默认值, ...)` 或 `.如果真 (是否为空 (参数_X)) 参数_X ＝ 值` 推断的实际默认值；源码若与参数尾注释（说明）矛盾，本文明确指出。
- 返回类型 `无` 在源码里写作空位（`.子程序 销毁, , 公开`）。
- 公共参数说明缩写（原文在下方展开，A 节用 `[P1]` 等标记代替，内容等价）：

# F. `字节集` 与 `文本型` 的实测语义（移植必须照此实现）

结论：**所有带 `W` 后缀的方法，其 字节集 都是 UTF-16LE（宽字符）文本，且以 `{0,0}`（一个宽字符 0）结尾；无 BOM。** 证据链：

1. `zyA2W (文本型) → 字节集`（`程序集_help.static.e.txt:4-20`）：`取文本长度 (参数_Ansi文本) ＋ 1` 交给 `MultiByteToWideChar`，`× 2` 分配 → 结果 **包含** 源串结尾 `#0` 转换出的 `0,0`，即 UTF-16LE + 终止符，**无 BOM**（代码页默认 936）。
2. `W末尾增加NULL`（`程序集_help:708-713`）：`取字节集右边 (字节集, 2) ＝ #空字符W` 判断后 `＋ #空字符W` → 明确「在 UNICODE 末尾增加 0,0」。`置代码W` 用它补终止符。
3. `_CloneString (字节集)`（`程序集_help`）：`len ＝ lstrlenW (str) × 2`、`HeapAlloc (…, len ＋ 2)`、`RtlMoveMemory` → **只按 `lstrlenW` 读**，因此传入 字节集 必须已以 0 结尾；`JsonValue_StringW`/`JsonValue_SetStringW`/`JsonValue_SetRawW` 全走这条，故 `创建文本W`/`置文本W`/`合并W` 的 字节集 必须是 NUL 结尾 UTF-16。
4. 返回侧统一是 `指针到字节集 (p, lstrlenW_Ptr (p) × 2 ＋ 2)`：见 `取属性名W`、`JsonValue_GetStringW`、`JsonValue_GetStringExW`、`JsonValue_GetRawW` → 长度 = 字符数×2 **+2**，即带 `{0,0}`；`×2` 是「宽字符→字节」的直接证据。
5. `zyString_GetStrW`：`指针到字节集 (sbPStr, sbStrLen × 2 ＋ 2)` → `到文本W`/`取文本W` 的返回值同样是 UTF-16LE + `{0,0}`。
6. 空值表示：
   - 空 UTF-16 文本 = `{ 0, 0 }`（`置代码W` 用它判空、`取属性名W`/`取文本W` 用它表示「无」）；`{ }`（空字节集）也被 `取文本W`/`置文本UTF8` 当作空。
   - `取文本W` 的字面量对照（原文）：`"" ＝ { 34, 0, 34, 0, 0, 0 }`、`{} ＝ { 123, 0, 125, 0, 0, 0 }`、`[] ＝ { 91, 0, 93, 0, 0, 0 }`、`null ＝ { 110,0,117,0,108,0,108,0 }`（±`{0,0}`）——每个可见字符后跟一个 `0` 字节，正是 UTF-16LE。
7. 长度参数：`JsonValue_Parsed3` 的 `strLen` 是 **宽字符个数**（不含终止符）：`置代码`/`置代码W` 用 `_取文本长度W`（= `lstrlenW`），`解析W`/`解析` 直接 `lstrlenW`；解析循环 `判断循环首 (i ≤ strLen)` 以 `i × 2` 为字节偏移取 `_指针到短整数U`，`wchar ＝ 0` 被当空白跳过（**所以 BOM 会被忽略吗？不会**：`0xFEFF` 落入「默认」分支交给 `jsonValue_parsed_other`，会产生错误 → **调用方需自行剥 BOM**）。
8. `文本型` 参数/返回：默认是 **ANSI/GBK (cp936)**（`zyA2W`/`zyW2A_Point` 默认代码页 936）。例外：名称含 `UTF8` 的方法，其 `文本型` 内放 **UTF-8 字节**：
   - 入参：`置代码UTF8`（`参数_JSON文本`）、`K_UTF8`（`参数_属性名`、`参数_路径`）、`置文本UTF8`（`参数_文本值`）、`置文本数组UTF8`（`文本数组` 元素）。
   - 出参：`取文本UTF8` 返回 UTF-8 字节的 文本型。
   - 名称带 UTF8 但与编码无关：`置数值数组UTF8`/`置整数数组UTF8`/`置逻辑数组UTF8`（内部只调 A 版 `置数值/置整数/置逻辑`）。
9. 逐项 文本型/字节集 对照表（公开 API）：

| 语义 | 文本型 版（ANSI/GBK） | 字节集 版（UTF-16LE+{0,0}） | UTF-8 版（文本型装 UTF-8） |
| --- | --- | --- | --- |
| JSON 源码入 | `置代码`、`解析`、`合并` | `置代码W`、`解析W`、`合并W`、`置文本W`(值)、`创建文本W` | `置代码UTF8`、`合并`无、`置文本UTF8`(值) |
| JSON 文一出 | `到文本`、`取文本`、`取源数据`、`取属性名` | `到文本W`、`取文本W`、`取源数据W`、`取属性名W` | `取文本UTF8` |

10. 值得在 C++ 里保留的编码细节：
    - `置文本W` 补终止符的判断写的是 `取字节集左边 (参数_文本值, 2) ≠ { 0, 0 }`（**左边**），等价于「只要前两字节不是 0,0 就在末尾追加 0,0」；对已正确终止的串会再追加一次 `{0,0}`（多一个宽 0）。移植时如要严格兼容旧行为，照抄「判左追加右」；如要修正，见 H-6。
    - `到文本W`/`取文本W` 空对象返回时 `zyString_GetStrW` 可能返回 `{ }`（空字节集），`取文本W` 把 `{ }` 与 `{0,0}` 同等对待。
    - `合并W` 的 字节集 被 `JsonValue_Combine` 当作指针直接用（`_取指针字节集` + `lstrlenW_Ptr`），**不复制前先补 0**，故调用方必须自己保证 `{0,0}` 结尾（这是与 `置代码W` 的差异，`置代码W` 会主动补）。

3. `初始化 ()` 被大量「置…」方法调用，但 `清空`/`清空W`/`置属性`/`置属性W`/`添加成员`/`插入成员`/`移除*`/`取类型*`/`取父*`/`取键数量*`/`合并对象Plus`(有)/`合并数组`(无)/`取源数据*`/`取文本*`/`取逻辑*`/`取双精度*`/`取数值*`/`取长整数*`/`取整数*`/`排序*`/`复制*` 中调用情况不统一：只有 `K*`、`I*`、`置对象*`、`置数组*`、`置文本*`、`置空*`、`置逻辑*`、`置双精度*`、`置数值*`、`置长整数*`、`置整数*`、`合并`、`合并W`、`合并对象`、`合并对象Plus` 里显式写了 `初始化 ()`。新库可统一改为「取指针前懒初始化」，但对 `JsonValue_SelectA` 传 0 指针的路径要保持容错（`JsonValue_SelectW` 的 `jsonValue ＝ 0` 分支会直接返回 0）。
4. 参数顺序不统一（**必须原样保留**）：
   - 「路径在前」：`置属性`、`置属性W`、`添加成员(W)`、`插入成员(W)`、`置成员(W)`（索引在前路径第二）、`插入属性(W)`、`取所有值(W)`。
   - 「属性名/索引在前」：`移除属性(W)`、`K(KW/K_UTF8/K2/K2W)`、`I(IW/I2/I2W)`、`置文本(W/UTF8)`、`置逻辑(W)`、`置双精度(W)`、`置数值(W)`、`置长整数(W)`、`置整数(W)`、`取所有键(W)`（输出数组在前，路径在后）。
5. `置整数(W)` 尾注释写「改变类型为长整数型」，实际调 `JsonValue_SetInt`；`取整数(W)` 用 `JsonValue_GetInt`。
6. `置文本W` 的终止符检查用 `取字节集左边`（应为右边），会重复追加 `{0,0}`；同时 `置文本UTF8` 先判了两次 `是否为空 (参数_路径)`。
7. `排序(W)` 的 `参数_算法` 虽被传给 `JsonValue_Sort`，但 `JsonValue_Sort` 内两次调用 `Array_Sort (…, 0)` 写死 0 → 目前**始终走快速排序**（`_Array_FastSort`）。
8. `取所有键(W)` 的双重语义：传空数组＝查询数量；传已定义数组＝填充。`取所有键W` 的数量分支调 `取键数量W`，`取所有键` 调 `取键数量`。
9. `置代码`/`置代码W` 在 `集_是否为顶层＝假`（即在子对象上调用）时不重建根，而是 `清空 ()` + `合并/合并W (…, 真)`。
10. `创建*` 系列（`创建对象/数组/空/逻辑/文本/文本W/双精度/长整数`）依赖 `_取指针对象 (m_object)` 作为父指针传入，指针为 0 时 `JsonValue_*` 用 `GetProcessHeap ()` 新建 → 等价于静态方法（源码尾注释即「可以看成静态方法」）。
11. `A-08`~`A-15` 的 `创建*` 返回前额外 `JsonValue_Release (this)`（因 `置指针` 已 Addref），新库需保持引用计数平衡，否则泄漏或提前释放。
12. `分离` 无参数、直接对当前对象 `JsonValue_Detch`；`销毁` 仅 `m_object.清除 ()`，不写 `集_是否已初始化 ＝ 假`（销毁后再使用同一对象时 `初始化 ()` 仍会直接返回真 → 已知不一致，兼容实现时建议同步复位标志或在文档标注）。
