# 创想浏览器插件对接（cxbrow）1.8.2

给易语言采集程序用的本机对接支持库：在本机起一个只监听 127.0.0.1 的 HTTP 服务，
让「创想浏览器插件」（Chrome / Edge 扩展）在亚马逊页面上把当前网址送进来，
插件与采集程序的连接、断开、重连都由库在后台自己管，数据以易语言自定义类型回调给绑定的子程序。

版本：1.0.0 首版 → 1.1.0 回调改成「整数句柄 + 还原事件信息 + 应答采集事件」（1.0.0 的参考结构体形参过不了易语言编译期 10063）→ 1.2.0 出口保证 UTF-8、去掉 `SO_REUSEADDR`、加 `模拟插件事件` → 1.3.0 **默认库内自动派发**（`置回调线程`），不用调泵 → 1.3.1 报错与日志改成单一 UTF-8 并带上变量地址 → 1.3.2 `还原事件信息` 两种取块形态都认，且明确「事件」变量要先赋一次值。共 32 条命令；事件结构体 21 个成员（1.6.0 带「任务名」，1.7.0 带「任务编号」+ 事件类型 4 撤回，1.8.0 带「已连接浏览器数量」+ 事件类型 5 全部浏览器断开）。
1.8.0 **多台浏览器**：会话按 `(扩展 ID, 浏览器名)` 一人一条（最多 16 条），每台各自按 `置连接超时秒` 判离线；

## 一、通信口径

| 项目 | 值 |
| --- | --- |
| 方式 | 本机 HTTP/1.1，扩展是客户端，采集程序是服务端 |
| 监听 | `127.0.0.1`，端口段 47630–47633，占用自动顺延 |
| 服务标识 | 握手回包里 `service = "cxac"`，扩展按这一串认领服务 |
| 会话串 | 每次成功绑定端口重新生成（32 位十六进制），后续请求走请求头 `x-cxa-key` |
| 扩展上报 | 请求头 `x-cxa-ext`（插件版本）、`x-cxa-ext-browser`（浏览器与版本）、`x-cxa-ext-id`（扩展 ID）—— 1.8.0 起 `(扩展ID, 浏览器名)` 就是会话主键，同一台机器上 Chrome 与 Edge 各算一台；打包 CRX 在两个浏览器里 ID 相同，所以只按 ID 分会并成一台 |
| 采集程序上报 | 握手回包 `version`（软件版本）、`app`（程序名称）、`browsers`（当前在线台数，1.8.0 起） |
| 编码 | 跨库边界的文本一律 UTF-8 原样透传，库内不做 GBK 转换 |

端点（都在 `/cxa/` 前缀下，与 EC 同一套语义）：

```
GET  /cxa/handshake   → {ok,service,bridge,version,app,ready,port,key,browsers}   免会话串
GET  /cxa/sites       → {ok,ready,siteCount,sites:[{platformName,displayName,host,homeUrl,
                         country,currency,language,pageTypes:[{type,title}],canList,canDetail,auth}]}
GET  /cxa/match?url=  → {ok,identifiable,universal,platformName,displayName,pageType,
                         colModType,canDetail,auth,name,country,currency/language,asin}
POST /cxa/task        ← {url,start,title,asin}   扩展把当前页面送进来
POST /cxa/recall      ← {taskId}  → 回执 {ok,removed,taskId,message,queueCount,started,recalledAt,seq}
                                    扩展点「撤回」，转成事件类型 4；queueCount/started 就是采集程序
                                    在 应答采集事件 里填的「队列数量 / 是否已开始」，recalledAt 与 seq 由库盖
POST /cxa/disconnect  → {ok:true}                扩展主动断开
```

失败统一 `{ok:false,code,message}`：`key_required`(403)、`not_found`(404)、`method_not_allowed`(405)、
`url_invalid`/`bad_json`/`can_not_identify_url`(400)、`no_binding`(503)、`reply_timeout`/`rejected`(500)。
跨域只在来源是 `chrome-extension://` 之类时回显 Origin，并带 `Access-Control-Allow-Private-Network: true`
（不带这一条，https 页面里的扩展打不开本机端口）。

1.5.0 起 `绑定事件子程序` 多一个可选参数「子程序名」：把 `&接收浏览器事件` 那个名字原样传一遍，
   日志与「派发异常」报错会点名是哪个子程序（不传只是少了这个名字，功能不变）。

会话模型（1.8.0）：会话串 `x-cxa-key` 是全机共用的一份（每次成功绑定端口重生成），**一台浏览器一条会话**按
`(扩展ID, 浏览器名)` 认领，表最多 16 条（满了把最久没露面的一条让位给新来的，只写日志不补发断开事件，避免在登记路径里套出递归派发）。
每条会话自己记 `dwLastReq`，`SrvTick` 每秒扫一遍：谁超过 `置连接超时秒` 没露面就单独判它断开。
`disconnect` 接口只撤发起方自己那一台，且用「不新建」模式登记 —— 陌生浏览器的断开请求不建会话、不改心跳、不发事件（否则一条野请求就能顶出「已连接+已断开+全部断开」三条）。

## 二、数据怎么进到易语言

1. `初始化对接 (软件版本, 运行目录, [程序名称], [服务标识], [起始端口], [端口数量])`
2. `绑定事件子程序 (&你的子程序)` —— 子程序形参**只能是一个整数型事件句柄**
3. `启动对接服务 ()` —— 绑定端口并起后台线程；端口全被占时该命令返回假，但后台每 5 秒继续重试，腾出端口会自己监听上，程序不用管
4. 默认 `置回调线程 (0)`：库在自己的请求线程里直接回调你的子程序，**不需要调泵**。
   服务是每个请求一条工作线程，所以派发时库内串行加锁（`g_csDispatch`）：同一时刻只有一个线程在你的
   接收子程序里，全局变量/采集队列/界面不会被两条事件同时改，事件按到达顺序处理，排队也不丢。
   要换吞吐才 `置事件并发 (真)`（子程序必须自己可重入，且不保证顺序）；`置事件并发 (假)` 收回默认。
   要动界面就 `置回调线程 (1)`，再在主窗口时钟里 `处理插件消息 ()`（或在子线程循环 `等待插件消息 (超时毫秒)`），回调就落在该线程

为什么不是直接把结构体交给子程序：易语言编译期规定「被取地址的子程序形参必须是基本数据类型」
（错误 10063），自定义类型哪怕加参考也不行。所以拆成两步：

```
.子程序 接收浏览器事件
.参数 事件句柄, 整数型
.局部变量 事件, 浏览器事件信息

事件.事件类型 = 99            ' 必须先给这个变量赋一次值，易语言才会分配内存给库写
.如果真 (还原事件信息 (事件句柄, 事件))
    处理采集 (事件句柄, 事件)     ' 逐字段取用
    应答采集事件 (事件句柄, 真, 主键, “已开始采集。”, 假, 队列数, 真)
.如果真结束
```

事件到达后：库把这条数据排进队列 → 你在 `处理插件消息` 里被回调 → 回调返回后库才给扩展回包。
因此回调里的应答就是扩展看到的应答，可以直接动界面。等待时长由 `置应答等待毫秒` 控制（默认 15000），
超时扩展收到 `reply_timeout`，队列里这条会被摘掉，不会补派发。

句柄与内存保证：

- **只在回调期间有效**：事件挂在一张 64 槽的句柄表上（`g_cs` 保护），回调一返回就摘掉；
  拿过期或伪造的号调 `还原事件信息` / `应答采集事件` 一律返回假，绝不解引用（宿主有断言）。
- **内存归属独立**：事件内部文本归事件对象所有；`还原事件信息` 为调用者变量深复制文本，
  数据块与文本均使用易语言内存池，调用者变量赋值、清空或销毁时由易语言正常释放。
  重复还原到同一个变量会先释放旧文本，空变量槽会分配独立数据块，绝不返回事件内部地址。
  还原后的变量可在回调返回后继续使用；事件句柄仍只能在本次回调期间还原和应答。
- **线程安全**：入队/出队/句柄表/状态都在 `g_cs` 里；投递者与派发者各持一次引用，
  「应答超时」和「正在派发」两条路径不会同时回收同一个事件；多个线程同时调 `处理插件消息`
  也各自派发不同事件（同一事件不会被派两次）。等待超时只移除尚未派发的事件；已在回调中的事件由派发方持有引用直到回调结束，HTTP 超时路径不读取正在修改的应答字段。
- **取块形态（1.4.0 定论）**：`参考 事件, 浏览器事件信息` 传的是**变量槽地址**，槽里才是块指针
  （真机取证：`raw=[1 0 80000301 813fd2c 0 20001 ...]`，第 3 个字是槽地址、第 5 个字 `20001` = `MAKELONG(1,2)` 正是本库 1 号自定义类型）。`A` 槽里是可用块指针 → 写易语言自己的块；`C` 槽里是空 → 使用易语言内存池分配独立数据块并回填槽；`B` 地址本身就是块 —— 只有槽里的值正好是事件类型取值时才认（1.8.0 是 1–5），且这块能写满 21 个成员才认。命中的形态连同变量地址写进日志（`restore-A: 还原事件信息取块方式 = A 变量地址 0x…`），失败时「取对接错误」带 `nArg/szof/raw/blk`（参数个数、本库 `sizeof(MDATA_INF)`、参数表前 8 个字、哪几个字指向可写的 84 字节块）。

自定义类型 `浏览器事件信息`（21 个成员，全部是入参；块布局 = 21 个 4 字节槽位）：

| 成员 | 说明 |
| --- | --- |
| 事件类型 / 序号 / 到达时间 | 1 采集请求 2 一台浏览器已连接 3 一台浏览器已断开 4 撤回任务 5 所有浏览器已断开 |
| 网址 / 标题 / ASIN | 标题与 ASIN 由插件从页面取好带过来 |
| 页面类型 / 采集模式 | 1 列表 2 店铺 3 详情；采集模式 1 列表 2 详情 |
| 平台名称 / 站点名称 / 国家 / 货币 / 语言 | 如 `AmazonUs` / `美国站` / `US` / `USD` / `en` |
| 是否开始采集 | 插件上是「发送到采集」还是「只添加任务」 |
| 插件版本 / 浏览器名称 / 插件编号 | 客户环境三件套；**1.8.0 起这三项在采集/撤回/断开事件里取的是「发起那一次请求」的头**，不再读汇总位 |
| 请求内容 | 插件发来的原始 JSON；断开事件里放的是断开原因 |
| 任务编号 | 撤回事件（类型 4）要撤的那个号 = 当初 应答采集事件 回给插件的 taskId；其余事件为空 |
| 任务名 | 插件提交任务时带的 `taskName`（也认 `name`）；没带则库内按「站点名 + ASIN」自动补，列表页补页面类型，永不为空 |
| 已连接浏览器数量 | 1.8.0 起每条事件派发那一刻的在线台数：类型 2 含刚连上的这台，类型 3 是不含刚断开那台的剩余，类型 5 恒为 0 |

回给插件的结果走 `应答采集事件 (句柄, 是否接受, 任务编号, 提示消息, 已在队列, 队列数量, 是否已开始)`：
`任务编号` 留空按本条序号回；`是否已开始` 不置真则插件提示「已入队未开始」（如实反映，不是失败）。

站点名单与网址识别规则内置了 21 个亚马逊站点。提交给 AC 的国家代码限定为 `US`、`UK`、`CA`、`JP`、`DE`、`FR`、`IT`、`ES`、`MX`、`IN`、`AU`、`AE`、`SG`、`SA`、`TR`、`PL`、`SE`、`NL`、`BR`、`EG`、`BE`；不支持的站点任务会被拒绝（列表页 / 店铺页 / 详情页规则见 `bridge_site.cpp`）。
采集程序要改支持范围用 `置站点名单 (每行“平台名|站点名|域名|国家|货币|语言”)`，传空文本恢复内置；
`取网址识别 (网址)` 可以在不装浏览器的情况下核对规则。

撤回回执（1.7.1）：撤没撤掉看 `removed`，正文用采集程序自己那句，卡片显示「已撤回（撤回时正在采集，已停止）：那句　剩余 N 个任务」。

撤回事件的页面身份（1.7.2）：提交时库按「实际回给插件的号」登记一份页面身份（`g_taskRef` 256 条循环淘汰），
撤回时回填进事件，所以 `事件.页面类型 / 网址 / ASIN / 站点名称 / 任务名` 在类型 4 上也有值；
查不到登记（程序重启过、号是外来的）就只带号。

撤回：提交成功的卡片上带一颗「撤回」按钮（只在回包有 taskId 时出现），点了走 `Ac.recall(taskId)` → `POST /cxa/recall`，结果原地改写那张卡（`Ac.updateNotice`），不另弹第二张。AC 的任务号是采集程序自己填的字符串，不做数值转换（EC 那边是整数，别照抄）。

插件提交任务时带的任务名由 `ac-client.js` 的 `Ac.taskName(match, url)` 组成：站点显示名 + 详情页 ASIN /列表页搜索词（都没有则页面标题，截 40 字），`ac-content.js` 在 `addTask` 的 info 里一起送出；留空时库内仍会按同样口径补一个，所以 `事件.任务名` 永远有值。

## 三、浏览器插件侧

扩展那边在 `E:\dev\dotnet\Project\创想浏览器插件`：

| 文件 | 作用 |

```
node tmp\ac-probe-two.js "<Chrome UA>" connect       ' type=2 cnt=1 browser=Chrome 139
node tmp\ac-probe-two.js "<Edge UA>" task <url>      ' type=2 cnt=2 → type=1 cnt=2 browser=Edge
node tmp\ac-probe-two.js "<Edge UA>" disconnect      ' type=3 cnt=1，不发 5
node tmp\ac-probe-two.js "<Chrome UA>" disconnect    ' type=3 cnt=0 → type=5 cnt=0
```

宿主覆盖到的边界：会话串错/缺、`task` 用 GET、坏 JSON、不可采网址、没绑子程序、无人取消息的超时、
端口占用顺延、端口全占后腾出一个的自动重试、停止后重启、运行目录是中文（GBK）时日志仍能落盘、
四个端点回包都是合法 JSON、类别表布局、过期句柄还原/应答一律拒收、
两台浏览器各自上线/断开时的台数与事件顺序（含「一台断开不牵连另一台」「陌生浏览器的断开被忽略」），
事件变量的独立文本所有权、重复还原与回调后存活、未启动采集的连续 200 次提交内存回收、
无人调泵及采集/撤回回调在执行中超时后的内存回收和后续请求处理。

更新支持库后需重新编译采集程序，静态编译的 EXE 不会自动使用磁盘上的新版静态库。
如果落库显示 `[PENDING]`，表示 IDE 仍占用旧动态库；关闭 IDE 后将同目录 `cxbrow.fne.new` 替换为 `cxbrow.fne`，再打开工程编译。

## 五、日志

设置了运行目录后，对接过程写在 `<运行目录>\浏览器插件对接.log`（UTF-8）：
每台浏览器的上线/断开（带「还剩几台」）、每条采集请求（页面类型、网址、插件版本）、无人应答、监听中断与恢复。
目录是按 ANSI(GBK) 传进来的（`取运行目录()` 的老口径）时，文件名退成 `cxbrow.log`，避免路径解析不开。
`取对接日志路径 ()` 拿到完整路径，`写对接日志 (文本)` 可以把程序里的处理结果写进同一份文件，客服报障直接发这一个文件。

## 批量添加任务

EC、AC 均提供 `POST /cxa/tasks`，鉴权与单条 `/cxa/task` 一致，必须携带目标进程的 `x-cxa-key`。

```json
{
  "start": false,
  "tasks": [
    { "url": "https://www.amazon.com/dp/B0DJNJBVWG", "name": "商品一" },
    { "url": "https://www.amazon.de/s?k=keyboard", "name": "键盘列表", "start": true }
  ]
}
```

- `tasks` 为 1–100 个任务对象；每项必须包含非空字符串 `url`，可选 `start` 覆盖批次默认值。服务端省略批次 `start` 时默认 true；插件调用必须显式传入布尔值。
- EC 使用 `name` 作为任务名称；AC 使用 `taskName`（或 `name`），并支持 `title`、`asin`。可选文本参数必须是字符串。
- 服务端先校验整批结构，再依次复用单条任务受理逻辑；同一批次全部发送至一个采集进程，不拆分、不自动重试、不改投其他进程。
- 响应包含 `ok/total/processed/successCount/failedCount/remainingCount/results`；`results` 按输入顺序排列，每项包含从 0 开始的 `index`、`url` 及原单条任务回执（包括 `taskId/state/started` 或失败的 `code/message`）。
- 任一任务失败立即停止，失败项包含在 `processed` 和 `results` 中，后续项计入 `remainingCount`；之前已接收的任务保留，不自动撤回。批次执行回执为 HTTP 200，只有全部成功才 `ok:true`；参数、方法、会话错误使用原有 HTTP 错误码，整批不派发任务。
- EC 批量受理不逐项等待采集线程启动，`started` 仅表示回执时的真实执行状态；AC 每项仍走原来的采集事件回调与应答，易语言接收方不需要增加新事件。
- 插件批量调用最多等待 120 秒，超时后不重发；部分任务可能已经受理，应先在采集软件核对结果。单条提交仍按 3 秒超时处理。EC 正文上限为 64 KiB，AC 为 256 KiB。

插件页面与后台均支持 `CxaEc.addTasks(tasks, start, instanceId)`、`CxaAc.addTasks(tasks, start, instanceId)`；`instanceId` 必须来自对应客户端的在线实例快照。页面消息分别为 `cxa:ecTasks` 和 `cxa:acTasks`，由 `background.js` 转发至指定进程。此接口不新增页面按钮。
