易语言侧对接源码（创想浏览器插件对接 1.8.0）
================================================================

为什么是这个写法：易语言编译期规定「被取地址的子程序，形参必须是基本数据类型」（错误 10063），
自定义类型哪怕加参考也不行。所以回调只收一个整数型「事件句柄」，
数据用 还原事件信息 写进你自己的 浏览器事件信息 变量，处理结果用 应答采集事件 回给插件。

用法：把【一】整段贴进采集软件的一个代码集，【二】只在主窗口加一行 启动浏览器对接。
命令名、参数名与库内命令表逐字一致；带 [可空] 的参数在 IDE 里仍要把逗号补满。

1.8.0 起一台浏览器算一条会话（Chrome 和 Edge 各算一台，同一台浏览器多窗口只算一台）：
事件类型 2/3 是「某一台上线 / 某一台断开」，谁是谁看 事件.浏览器名称 与 事件.插件编号，
还剩几台看 事件.已连接浏览器数量；全部浏览器掉光另发事件类型 5（#事件类型_全部浏览器断开）。
只连一台浏览器时，2/3 的行为和以前一样，只是断开后会再多收到一条 5。

【二】主窗口里要加的一处（1.3.0 起不用再调泵）
----------------------------------------------------------------

窗口_创建完毕：

    启动浏览器对接 (“20260022”, 取运行目录 ())   ' 版本号换成你自己的，插件设置页与日志都会带

默认就是**库内自动派发**：插件一点「AC启动采集」，库在自己的线程里直接调你的 接收浏览器事件，
不需要时钟、不需要循环、不需要 处理插件消息。

要让回调回到界面线程上做（要直接刷列表框、进度条），才改成手动调泵：

    置回调线程 (1)                       ' 放在 启动浏览器对接 之前
    ' 然后主窗口放一个时钟，周期 200 毫秒：
    处理插件消息 ()

   或者在你自己的子线程里循环 等待插件消息 (1000) —— 回调就在那个线程执行。

两种模式的取舍：
  · 自动派发（模式 0，默认）：省事，但子程序跑在库的线程上，**别在里面直接操作窗口组件**；
    要动界面就把数据塞进你自己的队列，让界面线程去取。
  · 手动调泵（模式 1）：回调在调 处理插件消息 的那个线程（放主窗口时钟里就是界面线程），
    可以直接动界面；代价是必须一直调，忘了调插件就会提示「采集程序没有及时应答」。
  随时可切：置回调线程 (0|1)，取回调模式 () 看当前是哪种。

事件原子性（1.5.0 起库内保证）：服务是每个请求一条工作线程，所以默认把接收子程序串起来跑 ——
  同一时刻只有一个线程在你的子程序里，全局变量、采集队列、界面都不会被两条事件同时改，
  事件也按到达顺序处理。排队不会丢事件（前一条返回后立刻派发下一条），所以一般不需要动这个开关。
  确实要多线程跑才用 置事件并发 (真)：那时子程序必须自己可重入（自己加锁、不碰界面、不依赖顺序），
  事件先后也不再保证。收回用 置事件并发 (假)，随时可切。

【三】四条必须记住的规矩
----------------------------------------------------------------

  · 应答要在子程序返回前做完（模式 0 和模式 1 都一样）。子程序一返回，事件句柄立刻作废；
    模式 1 下没人来取消息，插件在「置应答等待毫秒」（默认 15000 毫秒）后收到「没有及时应答」。
  · 事件结构体里的文本（网址、标题、原始 JSON 等）由库持有，只在本子程序执行期间有效；
    要留下的值请赋值给自己的变量或写进任务表，不要把 事件 整个存到全局变量里回头再用。
  · 没应答也不会重复派发：这条事件会被摘掉，插件显示失败，用户再点一次就是新的一条。
  · 调 还原事件信息 之前先给「事件」赋一次值（如 事件.事件类型 = 99）。这样内存是易语言自己分配的，
    库往里写 21 个成员，取回的值只在本子程序执行期间有效；漏了这一句库也能代管一块内存取到值，
    但那份内存的归属不如易语言自己分配的干净。返回假只剩一种情况：句柄过期（在回调外调用）。

【五】常量与成员口径
----------------------------------------------------------------

  事件类型：1 收到采集请求  2 一台浏览器已连接  3 一台浏览器已断开  4 撤回任务  5 所有浏览器已断开
                                                              （#事件类型_收到采集请求 等）
  页面类型：0 未识别  1 列表页  2 店铺页  3 详情页            （#页面类型_详情页 等）
  采集模式：0 未识别  1 列表  2 详情                          （#采集模式_列表 等）
  连接状态：0 未启动  1 等待插件  2 至少一台已连接             （#连接状态_插件已连接 等）

  浏览器事件信息（21 个成员，全部是入参）：
    事件类型 序号 到达时间 网址 标题 页面类型 采集模式 平台名称 站点名称
    国家 货币 语言 ASIN 是否开始采集 插件版本 浏览器名称 插件编号 请求内容 任务名 任务编号 已连接浏览器数量
  任务名：插件提交任务时带 taskName（ac-client 里 addTask(url, start, { taskName: "十月选品" })，也认 info.name）；
    插件没带就空着？不会 —— 库按「站点名 + ASIN」自动补一个，列表页补页面类型，所以 事件.任务名 永远有值，
    直接拿去填你任务表的标题列。1.6.0 起新增这一项。
  回给插件的结果不再放结构体，改走 应答采集事件 (句柄, 是否接受, 任务编号, 提示消息, 已在队列, 队列数量, 是否已开始)。

【六】版本差异
----------------------------------------------------------------

  1.8.0 支持多台浏览器同时连：库里按「扩展 ID + 浏览器名」各记一条会话（最多 16 台，
        Chrome 与 Edge 装同一个打包插件时扩展 ID 相同，所以浏览器名必须参与分台）。
        每台各按 置连接超时秒 独立计时，谁掉线报谁；事件类型 2/3 变成「一台上线 / 一台断开」，
        新增事件类型 5 = 所有浏览器都断开（在线台数从 ≥1 归 0 时派发一次，恒带 已连接浏览器数量=0）。
        新增第 21 个成员「已连接浏览器数量」（派发那一刻的在线台数，五种事件都带），
        新增 取已连接浏览器数 () 与 取已连接浏览器清单 ()（每行一台：浏览器名|插件版本|扩展ID|已在线秒数）。
        取连接状态 的 2 改成「至少一台在线」，只连一台浏览器时 2/3 的行为与以前一致。
        注意：插件点「断开」只撤它自己那一台；不在在线清单里的浏览器发断开会被忽略（不登记、不派事件）。
  1.7.2 撤回事件自带页面身份：库记下「回给插件的任务号 → 那一页」，撤回时把 网址/页面类型/采集模式/
        ASIN/站点名称/任务名 回填进事件（最多 256 条，满了淘汰最老的；程序重启后查不到就只剩号，
        那时按号或按 ASIN 查你自己的表）。
  1.7.1 撤回带回执：你在 应答采集事件 里填的「队列数量」和「是否已开始」现在会原样回给插件，库再补上
        撤回时刻 recalledAt 与本条流水号 seq；插件卡片显示成「任务 #x 已撤回（撤回时正在采集，已停止）：
        你那句话　剩余 N 个任务」。拒收时也带 queueCount，插件把卡片改回可再点一次。
  1.7.0 新增「撤回任务」事件：插件提交后的卡片上多一颗「撤回」按钮，点了库收到 POST /cxa/recall，
        转成 事件类型=4 的一条事件交给你，事件.任务编号 就是当初 应答采集事件 回给插件的那个号；
        你用 应答采集事件 的「是否接受」表示撤没撤回（假 = 撤不回，插件卡片原样显示你填的提示消息）。
        常量 #事件类型_撤回任务 = 4，事件结构体同时多了第 20 个成员「任务编号」。
